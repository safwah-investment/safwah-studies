صفوة — مساحة مالية خاصة لكل مستخدم

الموقع: https://safwah-investment.github.io/safwah-studies/finance/
مشروع Supabase: safwah-finance / smoauitircohiosjicsi

طريقة الاستخدام:
يكتب المستخدم اسمًا لمساحته ويضغط «إنشاء مساحتي». ينشئ Supabase جلسة ضيف مستقلة، وكل مستخدم يضيف ويعدّل حركاته ومرفقاته الخاصة. الاسم للعرض فقط؛ تكراره لا يفتح مساحة شخص آخر. لا يعتمد التسجيل على البريد أو موافقة مدير.
تحفظ الجلسة في هذا المتصفح ويُتحقق من المستخدم لدى Auth عند إعادة فتح الموقع. لا يمكن استرجاع مساحة الضيف بالاسم بعد الخروج أو مسح بيانات المتصفح، ولا الدخول إليها من جهاز آخر. يوضح الموقع ذلك قبل الإنشاء وقبل الخروج. احتفظ بنسخة احتياطية من السجلات والمرفقات؛ تصدير Excel عربي متاح أيضًا.

العزل والحفظ:
RLS ودوال الخادم تعزل البيانات باستخدام finance_records.owner_id = auth.uid(). الواجهة تضيف مرشح المستخدم أيضًا، لكن العزل يعتمد على الخادم. لا تستعلم الواجهة عن المديرين أو طلبات اعتماد البريد.
حفظ الحركة يستخدم save_finance_record الذي يعيّن المالك من الجلسة ويمنع الكتابة فوق تعديل آخر. المرفقات في حاوية خاصة، وتتحقق السياسات من ملكية الحركة.
تحفظ الجلسة في مفتاح واحد safwah-finance-guest-session-v1. لا توضع رموزها في روابط أو التصدير المالي. التجديد يحفظ الرمز الجديد، والخروج يمسح مفتاح الجلسة والبيانات المعروضة. تعذر الاتصال يبقي الجلسة السابقة لإعادة المحاولة بدل إنشاء مساحة بديلة تلقائيًا.

البيانات السابقة:
دفتر safwah-finance-v1 المحلي لا يُحذف ولا يُنقل تلقائيًا. يمكن نقل سجلات ومرفقات المتصفح إلى مساحة المستخدم بعد تأكيد النقل، مع بقاء النسخة الأصلية. السجلات السحابية السابقة بلا مالك موثوق تبقى محفوظة ومعزولة ولا توزّع على مستخدم جديد.

الإعداد:
يجب تفعيل تسجيل الضيف في Supabase Auth وتطبيق ترحيل عزل المساحات قبل النشر. لا تعد تشغيل ملفات الإنشاء الأولي على المشروع الموجود. cloud-config.js يحتوي بيانات المشروع العامة فقط؛ يمنع وضع service_role أو مفاتيح سرية في الواجهة. مسار اعتماد البريد السابق لا تستخدمه الواجهة الجديدة. لا تحتاج هذه الطريقة SMTP أو مزود رسائل.

التحقق:
تغطي الاختبارات المحلية إنشاء جلسة بلا بريد أو كلمة مرور، والتحقق من الجلسة المحفوظة قبل القراءة، ومرشح المالك، وإزالة البيانات عند الخروج، وفشل الجلسة دون كشف السجلات، وتجديد الجلسة وتعارض الإصدارات والمرفقات. تبقى اختبارات الحسابات وExcel العربي صالحة. يجب التحقق من عزل قاعدة البيانات الفعلي بين مستخدمين قبل اعتماد النشر.

استقبال المدفوعات — ماي فاتورة:
الربط الحالي يستخدم رابط فاتورة جاهزًا من حساب التاجر السعودي في ماي فاتورة. يظهر قسم «الدفع الإلكتروني» لفواتير الإيرادات التي لها مبلغ متبقٍ، ويُحفظ الرابط داخل JSON الخاص بالحركة في مساحة المستخدم نفسها. يُفتح الدفع لدى ماي فاتورة، ولا يجمع الموقع بيانات البطاقات أو مفاتيح API.
أنشئ فاتورة دفع لمرة واحدة بالمبلغ المتبقي، ثم الصق رابطها واحفظ الحركة. المضيف المسموح للإنتاج هو sa.myfatoorah.com فقط عبر HTTPS، دون اسم مستخدم أو كلمة مرور في الرابط أو منفذ غير قياسي. لا تقبل الواجهة روابط التجربة أو نطاقات مشابهة.
تحفظ paymentLink.url وpaymentLink.amountHalalas قيمة المتبقي وقت إضافة رابط جديد. تغيير البيان أو المرفقات يحافظ عليهما. إذا تغيّر المبلغ المتبقي فلا يعاد اعتماد الرابط السابق تلقائيًا؛ يُطلب إنشاء رابط جديد. فتح الرابط أو نسخه أو الرجوع منه لا يضيف دفعة إلى السجل، ولا يعد إثباتًا لاستلام الأموال. يجب التحقق من لوحة ماي فاتورة قبل تسجيل السداد يدويًا.
هذا الربط لا يحتاج تعديلًا جديدًا في قاعدة البيانات؛ الحفظ والعزل والنسخ السابقة يدعمان حقول JSON الإضافية. السجلات القديمة بدون رابط تعمل كالمعتاد.

التفعيل التلقائي لاحقًا:
يتطلب حساب ماي فاتورة مفعلًا ومفتاح API سعوديًا محفوظًا في الخادم فقط. لا تضع المفتاح في cloud-config.js أو GitHub أو بيانات السجلات ولا ترسله في المحادثة. ينبغي قصر إصدار فواتير حساب صفوة على هوية مسؤول المؤسسة التي يعتمدها صاحب المشروع في الخادم، لأن التسجيل العام في الموقع يسمح بإنشاء مساحات ضيف.
لم يُفعّل إنشاء فواتير API أو Webhook في النسخة الحالية. التفعيل التلقائي يجب أن يستخدم V3 وLINK، ويحفظ معرّف الفاتورة والمبلغ SAR خارج JSON القابل لتعديل المستخدم، ويتحقق من السداد من خدمة المزود قبل أي تعديل مالي، مع منع التكرار. لا تفعّل استقبال مدفوعات فعلية بافتراض أن إعداد رابط يدوي يعني إعداد API.
